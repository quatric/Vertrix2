# Vertrix2 for Wii (playable single-player board)

1. Copy `boot.dol` and `meta.xml` into `sd:/apps/vertrix2/`.
2. Copy the original, unchanged `Vertrix2.vf` next to them, into `sd:/apps/vertrix2/`.
3. Launch **Vertrix2** through the Homebrew Channel. It opens on the original title screen; 1PLAYER starts a game. On the title screen the Left / Right buttons below step through the 18 characters, each with its own decor, head, blocks and music (a stand-in for the original's character screen, which is not recovered).

Controls follow the original's key screen (LEFT, RIGHT, PERMUTE on UP, DOWN, PAUSE; key delay NONE,
so holding a direction does not repeat). Input is merged from every controller, as GlowWii does:

| Action | Wii Remote (held sideways) | Classic Controller | GameCube |
| --- | --- | --- | --- |
| Left / right | D-pad up / down | D-pad left / right | D-pad left / right |
| Permute (cycle the blocks) | D-pad right, A, 1 or 2 | D-pad up | D-pad up |
| Down (fast drop) | D-pad left | D-pad down | D-pad down |
| Pause | + | + | START |
| Restart after game over | A or 2 | A | A |
| Exit | HOME | HOME | Z + START |

What runs: the recovered spawn, descent speed tables, horizontal moves, lock, figure and line
matching, collapse, score and random generators, drawing the original decor, character head,
block artwork and fonts from `Vertrix2.vf`. Menus beyond the title, the character screen, bonuses, opponents, sound effects and the rest of the application are not
recovered yet. Each head is placed by the centre point in HeadFileName.ini, anchored where Doc's head sits (the original's anchor is not recovered). The clearing flash, the Wii button assignment and the starting level counter (12) are platform choices, not recovered behaviour. Verified in Dolphin only, not on
hardware. See `docs/WII-GAME.md`.

## Game screen (HUD)

The decor is composed with the original HUD when a character loads: the 120 damier pieces of the
builder at 0x46b810 (`source/hud_layout.c`, generated by `tools/gen_hud_layout.py` from the
executable) are drawn through the recovered effect renderer using that character's
`Filtre/<name>.flt`, so every character gets its own metal, copper or stone frames. The board sits
at the executable's origin (186, 130) and is clipped to 120 x 312 pixels. Loading a character takes
a moment longer because the whole HUD is rendered once.
