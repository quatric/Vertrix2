# Rendering recovery

The port has verified VF asset decoding, original block-frame selection and Wii
texture preparation/upload code. It has no complete draw loop or playable Wii
application yet. Texture compilation/linking does not prove hardware rendering.

## Board coordinates and clipping

`vertrix_board_clip` recovers the complete routine at `0x42ff10`. Its inclusive
bounds are origin X through X+119 and origin Y through Y+311: the 5x13 board
with 24-pixel cells. Each bound retains original signed 16-bit wrapping. The
original object also sets its clip mode byte at +0x8e to 3; that mode's renderer
dispatch is still unrecovered.

`vertrix_board_cell_position` recovers the initial occupied-cell positioning
phase of `0x430930..0x4309f9` for cells whose object mode byte +0x44 equals 16.
The original traverses columns first, then rows. X is board origin plus column
times 24 plus the signed byte at board+0x15c+cell index. Y uses row times 24
and board+0x19d+cell index. Final object coordinates at +0x0e/+0x16 wrap to
16 bits. Other object modes call `0x4b14c0` and subsequently center the resource
within its cell using the centering helper described below.

Verification executes the full original clipping routine and the positioning
phase unchanged, supplying 65 occupied mode-16 objects and random signed offset
bytes. It covers 1,025 origins and 66,625 positions, including signed-word wrap
boundaries. Invalid cell indices are rejected without changing output coordinates.

```sh
python tools/verify_render_geometry.py /path/to/Vertrix2.exe --build-dir /path/to/scratch/render-geometry
```

Evidence: `docs/render-geometry-verification.json`.

Original resource measurement, object draw ordering, clipping dispatch, effects,
blending and final Wii draw integration remain unfinished.

## Resource centering within board cells

`vertrix_board_cell_center` recovers `0x4310ba..0x4310ee`, which follows the
resource measurement call for cells whose mode is not 16. Each coordinate adds
`(24 - measured_dimension) >> 1`, with wrapping unsigned 32-bit subtraction
and a logical right shift, then stores the low signed word. For a width of 25,
the final X moves left by one pixel, rather than using truncating signed division.
The current cell coordinate already includes the signed offset from the first pass.

Verification executes both branches of the complete first positioning pass,
intercepting only `0x4b14c0` to supply resource dimensions. It checks another
66,625 centered positions using zero, odd, oversized and signed-word boundary
dimensions. All match the unchanged original coordinate instructions. Resource
measurement itself, including transformed image sizes, remains unrecovered;
the helper must be supplied the actual measured width and height.

## Resource dimensions

`vertrix_resource_measure` recovers the dimension calculation at `0x4b14c0` for resolved modes 0 through 16. Mode 16 returns signed low-word dimensions directly. Smaller modes use a 16-by-16 remainder table generated by the original initializer at `0x4b9050`, rather than ordinary proportional rounding. `tools/recover_render_tables.py` reproduces that table from the verified executable.

The comparison executes the original measurement routine for 13,808 boundary and random cases, using both descriptor dimensions and object fallback dimensions. All match. Invalid native modes preserve output arguments. Wii compilation and formatting checks pass.

`vertrix_resource_measure_state` now selects descriptor dimensions when present, otherwise object fallback dimensions. Object mode applies unless the object screen-override byte is nonzero; then a nonzero screen unscaled byte selects mode 16, otherwise the screen mode applies. These branches match 10,000 additional randomized original executions, including nonzero flag values other than one. This pure calculation does not reproduce the renderer's global cache writes. Full drawing and application startup remain unfinished.

## Sprite bounds and anchors

`vertrix_resource_bounds` recovers the geometry returned by `0x4b15e0`. Descriptor words at +12/+16 are anchors subtracted from the signed high-word object position. At scale 16 the anchors apply directly. At smaller scales the original multiplies each signed measured dimension by its signed anchor, divides by the unsigned source dimension with truncation toward zero, then wraps the scaled anchor to a signed word. This means bounds coordinates are full signed integers, not wrapped board coordinates.

10,000 random descriptor cases, including negative anchors and source dimensions above 32767, match full original routine execution. The native function rejects zero source dimensions for scaled modes because the original would divide by zero. Descriptor absence uses zero anchors; mode selection remains available through the separately recovered state selector. Renderer global cache writes, clipping and drawing remain to be integrated. Wii compilation and formatting checks pass.

## Unscaled sprite clipping

`vertrix_sprite_clip` recovers the unscaled intersection stage at `0x4b1ae9..0x4b1c6f`. Inputs are the positioned sprite and resolved inclusive clip rectangle. Signed-word endpoint comparisons reject offscreen sprites. Top clipping advances the source offset by removed rows times the signed original width; left clipping advances it by removed columns. The native result preserves wrapping offsets, clipped endpoints, word-sized visible dimensions and the original clipping flag. It returns zero without changing output for empty or rejected sprites.

20,000 comparisons execute the original phase: 10,000 ordinary board-edge cases and 10,000 arbitrary signed-coordinate, dimension and rectangle cases. Original rejection is intercepted at `0x4b1d44` and redirected to the phase endpoint before the surrounding function epilogue. This verifies the geometry phase, not the complete renderer. The mode dispatcher, scaled source sampling, graphics cache, pixel blending and Wii drawing remain unfinished.

## Surface addressing and pixel access

`surface.c` recovers addressing from `0x478eb0`: base plus row times stride plus column times bytes per pixel, with low-32-bit arithmetic. The standalone offset function reproduces wrapping without using host pointers. Original descriptor +0x14 is row stride and +0x0c is bytes per pixel.

Pixel reads (`0x478f10`) and writes (`0x478ed0`) support 1, 2 and 4 bytes. The portable implementation explicitly decodes and encodes little-endian values so PowerPC host byte order cannot reverse Windows pixel data. Surface operations validate coordinates, row storage and allocation bounds before access. They preserve output/storage on invalid access. Original renderer cache global writes are not reproduced.

10,000 arbitrary signed coordinate/stride/format offset cases and 6,000 padded surface read/write cases match unchanged original execution. Full surface bytes are compared after each write, including untouched pixels and padding. Out-of-range coordinates are also checked for unchanged output. Wii compilation and formatting checks pass. Blending, scaled sampling and full drawing remain unfinished.

## Drawing routine selection

`render_dispatch.c` recovers the ordered rule matcher at `0x4af2a0` and original routine selection at `0x4b1fde`. The 92 rules at `0x4fed44` each supply required and additionally allowed flag bits. First match wins; a flag combination with no match returns index 92. The original `0x4ff024` table has four 92-entry rows for target formats 4, 2, 1 and 0. Other target-format bytes follow the original row-zero fallback. Unmatched rules and zero table entries select no routine.

`tools/recover_render_dispatch.py` extracts both tables from the fingerprint-verified executable. Original addresses are evidence identifiers only; the native port never calls them. They identify which drawing bodies still need recovery and must eventually map to native implementations. Flag construction at `0x4af370` is now recovered below; drawing bodies and full rendering integration remain unfinished.

19,200 rule comparisons and 115,200 routine selections match original execution. Tests exercise required flags with random allowed subsets, unrestricted random flags, all four format rows and two fallback format bytes. Wii compilation and formatting checks pass.

## Direct pixel kernels

Rule zero (flags `1`) selects a 32-bit copy at `0x48d720`, RGB565 conversion at `0x49b4a0`, RGB555 conversion at `0x4933e0`, or RGB332 conversion at `0x4a3540`. Target-format identifiers 4, 2, 1 and 0 are format identifiers, not bytes per pixel: RGB555 and RGB565 both write two bytes. Other target identifiers retain the dispatcher row-zero behavior. Flags `0x100000` alone match no rule, so they do not authorize a direct kernel.

`vertrix_render_direct_pixel` reproduces these channel masks and truncating shifts. The 32-bit path preserves alpha bits; reduced formats discard them. `vertrix_render_direct_write` connects conversion to the bounded, endian-explicit surface writer, rejecting incompatible storage formats. Source channel order is defined by packed bit positions rather than inferred from a host integer layout.

30,000 random source-word comparisons execute the four original kernels and compare both output values and entire sentinel-padded storage, including unaligned writes. Two dispatcher fallback format values are covered. The existing 10,000 offset and 6,000 surface access cases also pass. Wii compilation and formatting checks pass. Per-pixel direct conversion is now recovered; blended kernels, scaled sampling, traversal and application drawing remain unfinished.

## Packed effect pixels

`vertrix_render_effect_pixel` recovers seven 32-bit amount-50 kernels without palette transformation: effects 1 and 3 (`0x48db70`, `0x48dcd0`) half-blend source and destination, rounding each operand down separately; effect 4 (`0x48dd00`) performs packed saturating addition; effects 5 and 6 (`0x48dd50`, `0x48dda0`) perform packed subtraction in opposite directions; effects 7 and 8 (`0x48ddf0`, `0x48de10`) invert source or destination. All discard alpha. Packed addition/subtraction preserve the original `0xfefeff` mask and carry/borrow expressions, including discarded channel bits. They are not replaced with conventional channel arithmetic.

35,000 random source/destination comparisons match unchanged original kernel execution. Unsupported effects preserve native output. Prior direct-pixel and surface comparisons continue to pass, as do Wii compilation and formatting. This covers these seven pixel operations only: transparent traversal, palette transforms, other amounts, other effects and full drawing remain unfinished.

Zero advances repeat source pixels; larger advances skip source pixels. The final advance is consumed without another sample. The native operation validates the last sampled position and destination row before writing.

2,000 random rows match complete original loop execution with the original `0x48d720` pixel kernel. Cases use advances from zero through five. Previous surface comparisons, Wii compilation and formatting checks pass.
