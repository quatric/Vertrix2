# Executable entry map

- Entry `0x4eb454` is the Borland startup stub (`jmp 0x4ec200`); the app is a
  Delphi/VCL program, so there is no plain Win32 message loop to find. The game
  loop is reached through VCL events, not a PeekMessage call.
- Platform functions that the Wii port replaces with libogc rather than
  recovering by hand: DirectDraw setup `0x484b60` (2,362 bytes, calls
  `DirectDrawCreateEx`) and the DirectInput creators `0x476aa0`, `0x477390`,
  `0x477b10`.
- The call graph (`callgraph.json`) is generated by `work/` scripts from
  `disassembly.txt` and is not a deliverable. Addresses cited in the recovery
  notes as families or ranges (for example the `0x4ac500`/`0x4ac600` timer
  families, `0x4ac1f0..0x4ac310` animation) count as recovered even though
  individual addresses are not listed. Counting 8-digit addresses and ranges, 297 of 1,499 game-range functions (about 114 KB of 360 KB, roughly 32%) are recovered.
- Largest unrecovered game routines by size: `0x466d60` (10 KB, 361 calls),
  `0x46c9d0`, `0x4633b0`, `0x43d3d0`, `0x485700`, `0x46f440`, `0x465af0`.

Oracle setup: `python3 -m venv work/.venv` and install
`tools/requirements.txt`; run verifiers as
`work/.venv/bin/python tools/verify_X.py work/extraction-check/original/Vertrix2.exe --build-dir /tmp/vb`.
