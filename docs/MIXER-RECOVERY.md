# Original software mixer recovery

`mixer.c` begins recovery of the original software mixer, alongside the VF audio resource loaders.

The successful sample attachment path at `0x40c9d0..0x40ca60` resets sample position to zero. Nonlooping samples use byte count for both boundaries. Native sample flags 0x10 or 0x20 select explicit loop boundaries; 0x20 also enables ping-pong playback. Native sample flag 1 selects sixteen-bit data and arithmetic right shifts boundaries by one to convert byte positions. All positions are then shifted left twelve bits, preserving original 32-bit wrapping. The resulting channel flags are stopped 1, sixteen-bit 2, looping 4 and ping-pong 8. `vertrix_mixer_cursor` reproduces this geometry without embedding original executable pointers.

Original frequency setter `0x40cb10` accepts frequencies 512 through 524,288 Hz and computes an unsigned fixed-point step as `((frequency << 12) + (output_rate >> 1)) / output_rate`, with original unsigned wrapping before division. `vertrix_mixer_step` reproduces the calculation, preserves output on invalid input, and additionally rejects zero output rate to avoid the original division fault.

`tools/verify_mixer_cursor.py` executes the original attachment and frequency routines, checking 20,000 cursor cases and 20,000 step cases. All agree, including sixteen-bit boundary conversion, upper sample flag bits, ping-pong flags and fixed-point wrapping. Native invalid-frequency and zero-rate guards also pass. PowerPC library compilation and formatting checks pass. Evidence is in `mixer-cursor-verification.json`.

The original noninterpolated stereo kernels `0x401328` (eight-bit) and `0x402c18` (sixteen-bit) quantize stereo gains from the stored channel volume. Setter `0x40cb70` accepts public volumes 0..64 and stores volume divided by two, giving 0..32. Pan 0..15 uses full left gain; 240..255 uses full right gain. Pan 120..135 uses half the stored volume on both sides, rounded down independently. Other pan values use right gain `(pan * stored_volume) >> 8` and left gain `stored_volume - right_gain`. `vertrix_mixer_stereo_gains` preserves these thresholds and rounding, including the center reduction for odd stored volumes.

`tools/verify_mixer_gains.py` initializes the original gain table with `0x40c7d0`, then executes both complete stereo kernels for all 33 stored volumes and 256 pan values using one positive sample. All 16,896 output pairs agree. Evidence is in `mixer-gains-verification.json`. This verifies gain selection in the noninterpolated paths; arbitrary sample values, interpolation and complete playback remain unverified.

The stopped flag interpretation is corrected from the earlier documentation: mixer `0x40c460` skips channels with bit 1 set; `0x40ca70` clears that bit to start, and `0x40caa0` sets it to stop. Sample attachment starts stopped. The recovered cursor bits already matched the executable; only their previous label was wrong.

Verification covers successful cursor geometry and playback-step arithmetic. It excludes source-pointer ownership, slot validity, per-frame cursor advance, loop crossing, interpolation, general sample accumulation, output conversion and music tick/effect handling. This remains a partial recovery rather than a working mixer or complete game.

## Signed sample volume table

`vertrix_mixer_pcm8_value` reproduces the main signed 32-bit lookup table generated by `0x40c7d0`. Raw sample bytes represent signed samples -128..127. Each entry is the sample multiplied by table row and master gain, arithmetic shifted right four bits. Mono mode first halves the master gain, rounding down. Negative products round toward negative infinity; the portable C implementation uses explicit division with correction rather than relying on implementation-defined signed shifts. Table rows 0..64 and master gains 0..256 match the original initializer's accepted range. Native invalid arguments preserve the destination.

`tools/verify_mixer_table.py` executes the complete original initializer 514 times, covering both mono/stereo modes and every accepted master gain. It compares all 65 rows and all 256 sample byte values: 8,552,960 table entries agree. Invalid native argument checks, Wii library compilation and formatting checks pass. Evidence is in `mixer-table-verification.json`.

This supplies original signed sample scaling for subsequent mixing. The auxiliary byte table, sample accumulation, interpolation, output conversion, XM tick/effect processing and complete audible playback remain unfinished.

## Output conversion

`vertrix_mixer_output` recovers the complete conversion loops at `0x401010` and `0x401054`. Sixteen-bit output clips signed accumulation to -32768..32767 and emits little-endian sample bytes. Eight-bit output adds an unsigned bias of 32768, clips ordinary values to 0..65535 and emits the upper byte. This is unsigned PCM8, with silence at 128.

The eight-bit original uses `ADD/JL`, followed by a signed comparison. At extreme positive accumulation where adding the bias overflows signed 32-bit range, the overflow flag prevents the first clamp and the wrapped signed comparison prevents the second. The original emits the wrapped upper byte in that case. The C implementation explicitly preserves this behavior using unsigned arithmetic. Native capacity and null checks reject invalid buffers before writing; zero count is a no-op instead of entering the original unconditional first iteration. Caller-provided valid, separate source/destination buffers are required.

`tools/verify_mixer_output.py` executes both complete original loops and checks 367,704 converted samples: every integer from -65536 through 65536, the complete positive-overflow range and nearby values, INT_MIN, and 20,000 random signed 32-bit values. All emitted bytes match. Native capacity/null/zero-count checks pass. Evidence is in `mixer-output-verification.json`. This recovers output conversion only; sample accumulation, loop traversal, interpolation, XM tick/effect processing and complete audible playback remain unfinished.

## Interpolation smoothing recurrence

Original PCM8 mono interpolated kernel `0x401cd0` falls back to its noninterpolated path when signed playback step is at least 4096 or at most -4096. For smaller absolute steps, its weight is `abs(step) >> 7`, selecting one of 32 rows in the auxiliary byte table generated by `0x40c7d0`. Each auxiliary entry is a signed sample multiplied by weight and arithmetic shifted right five bits, stored as a byte.

The recurrence updates the previous filtered byte as `previous - table[previous] + table[current_sample]`, wrapping to eight bits. It then uses that filtered byte for the normal volume lookup. The resulting byte persists in original channel +23 for the next output frame. This is stateful smoothing rather than a conventional blend of adjacent source samples. `vertrix_mixer_filter` reproduces the recurrence with explicit signed floor division and unsigned byte wrapping. Weight zero preserves the previous byte.

`tools/verify_mixer_filter.py` executes the complete original PCM8 mono interpolated kernel for one frame per fixture, comparing both output contribution and persisted filtered byte. All 28,192 cases agree: all quantized weights and previous byte values, random current samples and signed forward/reverse/zero steps strictly inside the fallback bounds. Invalid native weights preserve output; null output is rejected. Evidence is in `mixer-filter-verification.json`. Wii compilation and formatting checks pass.

This recovers the scalar smoothing recurrence. Complete interpolated batches, large-step fallback integration, other interpolated kernels, loop traversal, XM tick/effect processing and full audible music playback remain unfinished.

## Batch sizing at sample boundaries

`vertrix_mixer_batch` recovers arithmetic at `0x40c518..0x40c547` for a cursor ready to mix. Distance is position minus start for reverse traversal, or end minus position for forward traversal. If the wrapped unsigned product `step * remaining_frames` exceeds distance, the original computes batch length by signed division of the wrapped `distance + step` by positive step magnitude. Otherwise it retains the requested length. Reverse traversal temporarily negates the step bits before calling a kernel. This preserves the original extra boundary sample when a shortened batch lands exactly on a boundary.

The native helper accepts positive magnitudes 1..INT32_MAX and rejects zero/invalid magnitudes or null pointers before changing output. The surrounding mixer must establish a ready cursor and usable batch length before dispatching a bounded sample kernel.
